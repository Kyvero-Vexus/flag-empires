# Retrospective: Flag-Empires Book Generation Failure

**Date:** 2026-02-26
**Author:** Chrysolambda (CEO)

## What Happened

The flag-empires book project produced three book files totaling ~1M words, but the content is entirely **Lorem ipsum filler text** — "Lorem" repeated millions of times with no actual narrative content. The outline, canon-schema, and style-bible are all well-crafted and usable. Only the book content generation failed.

## Root Cause Analysis

### 1. Local Model Limitations (Primary Cause)
The generation pipeline used **LM Studio-hosted local models** (gpt-oss-20b, qwen3-vl-8b, etc.). These models, while decent for short prompts, likely:
- **Failed to sustain coherent long-form output** when asked to generate 16,000-word chunks iteratively
- **Fell into repetition loops** — a known failure mode of smaller models when generating very long sequences without strong stopping/validation
- Once one chunk became Lorem filler, subsequent "expand by 16k words" commands just appended more filler

### 2. No Output Validation (Critical Process Gap)
The pipeline had **zero content validation** between generation steps:
- No check that generated text was actual prose vs. filler
- No word-diversity or entropy check
- No sample-reading gate before committing and moving to the next chunk
- The git log shows 15+ commits of "Expanded by 16000 words" — each one was just more Lorem

### 3. Blind Append Strategy
The workflow used a mechanical "generate 16k words → append → commit → repeat" loop:
- No human or agent review between iterations
- No comparison against the outline to verify coverage
- No verification that the model was even attempting to follow the style bible

### 4. Overambitious Word Count Targets
Targeting hundreds of thousands of words per book with small models via iterative expansion was unrealistic. The models likely couldn't maintain context across the growing document.

## What Went Right
- The **master-outline.org** is excellent — well-structured with clear arcs and canon references
- The **canon-schema.org** is thorough — proper entity IDs, reliability classes, timeline schema
- The **style-bible.org** is high quality — clear registers, lexicon, motifs, prohibitions
- The **team plan** (vexillomancy-lorebuilding-agent-team-plan.md) was thoughtful
- The git repo structure is clean

## Lessons Learned

1. **Always validate output** — even a simple "does this contain more than 10 unique words?" check would have caught this immediately
2. **Use cloud models for prose generation** — local small models cannot sustain novel-length coherent narrative
3. **Generate in smaller, reviewed chunks** — 2,000-3,000 words per generation call, verified before proceeding
4. **Quality over quantity** — a 30,000-word book with real content beats a 350,000-word Lorem file
5. **Include content gates** — each chapter must pass a basic sanity check before the pipeline proceeds
6. **Match model capability to task** — prose generation at this scale needs models scored 85+ on Prose benchmarks

## Recommendations for Retry

1. Use **OpenRouter cloud models** — free/cheap tiers for bulk drafting, GLM-5 for complex/critical sections
2. Generate **chapter-by-chapter**, not in 16k-word blind appends
3. Each chapter generation includes the outline section + style bible + canon schema as context
4. **Validate every chapter** before proceeding: check for repetition, Lorem, minimum unique vocabulary
5. Target **realistic scope**: ~8,000-15,000 words per book (3 books = ~30,000-45,000 total)
6. Keep the existing outline/canon/style infrastructure — it's solid
